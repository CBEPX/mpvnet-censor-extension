# Онлайн-тайминги и собственный агрегатор

## Как это работает в плеере

1. Откройте фильм и окно `Цензура → Интервалы…`.
2. Нажмите `Найти онлайн…`. Проверьте подставленное название, при необходимости
   исправьте его и нажмите `Найти`.
3. Выберите результат и нажмите `Показать тайминги`. Вместо поиска можно сразу
   вставить ID Кинопоиска или ссылку вида
   `https://www.kinopoisk.ru/film/301/`.
4. Сверьте фильм и длительность. Законченные интервалы отмечены для добавления.
   Одиночные отметки, непонятный текст и запись `Чисто` видны, но не превращаются
   в интервал автоматически.
5. Нажмите `Добавить выбранные интервалы`. Они попадут в несохранённый черновик
   одной операцией, поэтому весь импорт можно отменить одним нажатием
   `Отменить`. В примечании останутся источник, ID Кинопоиска и ID исходной
   записи, например `[timings.rte kp:301 #2032]`. Если одна запись разбирается
   на несколько фрагментов, их позиция сохраняется в суффиксе `.2`, `.3` и так
   далее.

Для одиночной отметки доступно действие `Перейти и отметить начало`. Плеер
перейдёт к указанному месту; конец сцены нужно отметить вручную.

Онлайн-поиск не создаёт файл. После проверки примените интервалы, а затем
нажмите `Сохранить файл`, если нужен переносимый `*.censor.txt`.

## Источник и приватность

По умолчанию запрос отправляется напрямую на
`https://timings.rte.net.ru/api`. Запрос начинается только после нажатия
`Найти` или `Показать тайминги`. В поле поиска заранее подставляется имя файла
без каталога и расширения; перед отправкой его можно исправить или удалить.
Сервис увидит IP-адрес и отправленную строку поиска. CensorPlayer не отправляет
каталог файла, историю просмотра или уже созданные интервалы.

В настройках можно выбрать `Свой агрегатор`. Разрешён HTTPS; обычный HTTP
допускается только для локальных loopback-адресов, например `localhost`,
`127.0.0.1` и `::1`. Ошибка агрегатора
показывается пользователю, но не включает скрытый запрос к прямому источнику.
Если агрегатор выбран, но его сохранённый адрес некорректен, CensorPlayer
показывает предупреждение и очищает адрес, но не переключается на `timings.rte`
сам: следующий запрос завершится понятной ошибкой до исправления настройки.
В прямом режиме неиспользуемый адрес сохраняется как введённый и проверяется
только после выбора собственного агрегатора.
Название источника в примечании приходит из ответа агрегатора. Используйте
агрегатор, администратору которого доверяете.

## API агрегатора

Сервис находится в `src/Censor.Timings.Api` и предоставляет три GET-маршрута:

```text
GET /healthz
GET /v1/movies/search?q=Матрица
GET /v1/movies/kp/301/timings
```

Ответ поиска:

```json
{
  "schemaVersion": 1,
  "source": "timings.rte",
  "movies": [
    {
      "id": "301",
      "title": "Матрица (1999)",
      "year": "1999",
      "sourceDurationMs": 8160000
    }
  ]
}
```

Схема агрегатора строгая: запись с неверным ID, слишком длинным названием или
другими несовместимыми полями отклоняет весь ответ. Это позволяет заметить
ошибку собственного сервиса, а не молча показать неполный список.
`source` — короткий идентификатор до 100 символов: разрешены буквы, цифры,
пробел, точка, дефис и подчёркивание. Скобки и управляющие символы запрещены,
потому что идентификатор добавляется в примечание импортированного интервала.
`sourceEntryId` — положительный числовой ID записи `timings.rte`; произвольные
строки здесь не принимаются.

Ответ с таймингами сохраняет тип каждого фрагмента: `interval`, `point`,
`unparsed` или `clean-claim`. У интервала есть `startMs` и `endMs`, у точки —
только `startMs`. Поле `rawText` остаётся в ответе, чтобы пользователь мог
проверить разбор.

`sourceUrl` и `fetchedAtUtc` остаются обязательными сведениями о происхождении
данных для диагностики и других клиентов API. Плагин не выводит их в основное
окно, чтобы не перегружать обычный сценарий проверки и добавления интервалов.

Короткая запись `1:30` трактуется как `ММ:СС`, то есть как 1 минута 30 секунд,
а не как 1 час 30 минут. Перед добавлением такой отметки проверьте время в
таблице.

Ограничения сервиса:

- 30 запросов в минуту с одного IP;
- ответ 429 содержит `Retry-After`; `/healthz` не входит в ограничение;
- ответ внешнего источника не больше 1 МиБ;
- тайм-аут внешнего запроса 10 секунд;
- прямой ответ `timings.rte` ограничивается первыми 20 подходящими результатами
  поиска и первыми 500 разобранными фрагментами;
- больше 500 исходных записей таймингов в одном ответе `timings.rte` считается
  некорректным ответом;
- собственный агрегатор должен вернуть не больше 20 результатов поиска и 500
  кандидатов таймингов; нарушение его строгой схемы отклоняет весь ответ;
- кэш в памяти на 10 минут;
- учётный размер кэша ограничен 64 МиБ: учитываются байты JSON и не меньше
  512 байт на запись; общий расход памяти процесса проверяется отдельно;
- ответы upstream с ошибкой 429, 500, 502 и 504 кэшируются на минуту;
- параллельные одинаковые промахи кэша объединяются в один запрос к
  `timings.rte`, а разные фильмы не блокируют друг друга;
- одновременно к upstream выполняется не больше четырёх запросов;
- нет POST-методов, базы, телеметрии и пользовательских аккаунтов.

При прямом запуске дополнительная настройка IP не нужна. Если контейнер стоит
за reverse proxy, перечислите точные IP доверенных прокси через запятую:

```text
CENSORPLAYER_TRUSTED_PROXIES=172.18.0.2,172.18.0.3
```

Только от этих адресов сервис принимает один уровень `X-Forwarded-For`.
Заголовок от любого другого узла игнорируется, поэтому клиент не может обойти
ограничение частоты подменой этого заголовка. Для публичного IPv6-доступа
добавьте ограничение по префиксу сети на reverse proxy: перебор IPv6-адресов
иначе создаёт много отдельных лимитеров и расходует память контейнера. Если
адрес прокси меняется, закрепите его в сети контейнеров либо ограничивайте
запросы на самом прокси.

## Локальный запуск

`CENSORPLAYER_RTE_BASE_URL` предназначен только для тестов и совместимого
зеркала API `timings.rte`. Сервис по-прежнему указывает `timings.rte` как
источник данных и не раскрывает внутренний адрес зеркала в публичном ответе.

```sh
dotnet restore src/Censor.Timings.Api/Censor.Timings.Api.csproj --locked-mode
dotnet run --project src/Censor.Timings.Api/Censor.Timings.Api.csproj
```

Проверка:

```sh
bash scripts/smoke-timings-api.sh
docker build -f src/Censor.Timings.Api/Dockerfile -t censorplayer-timings .
docker run --rm --memory 256m -p 8080:8080 censorplayer-timings
curl http://127.0.0.1:8080/healthz
```

CI собирает контейнер на pull request. Ветка `main` публикует неизменяемый образ
`ghcr.io/<owner>/<repo>-timings:sha-<commit>` с SBOM и provenance, но только
после успешного workflow `CI` для этого коммита. Плавающий тег `edge` намеренно
не создаётся: быстрые последовательные публикации не должны отменять или
перезаписывать образ уже проверенного коммита.
После первой публикации владелец пакета должен проверить в GitHub Packages, что
видимость контейнера установлена в `Public`.

## Разрешение на агрегатор

Разрешение владельца `timings.rte` на использование API и работу публичного
агрегатора получено 19 августа 2026 года. Подтверждение и оговорённые условия
нужно сохранить в release record; личную переписку не следует добавлять в
публичный репозиторий без согласия участников.
