# Windows P0: финальная проверка

Проверку проводят на финальном x64-пакете (portable-сборке или установщике) с
точно зафиксированным SHA-256. Результаты проверки DLL из коммита `440269a`
подтверждают пройденные регрессионные тесты, но не заменяют проверку нового
пакета.

## Зафиксировать перед тестом

- хеш коммита, идентификаторы запуска GitHub Actions и артефактов, SHA-256 всех
  файлов;
- номер сборки Windows, модель GPU и версию драйвера, версии
  mpv.net/libmpv/FFmpeg;
- тип пакета (portable-сборка или установщик) и сценарий: чистая установка,
  обновление или откат;
- кодек, разрешение, FPS и длительность файла, значение `hwdec-current`;
- расписание, обезличенные журналы и считанное значение `vf`.

## Артефакты и установка — блокирующие проверки

- [ ] Контрольные суммы из `SHA256SUMS.txt` совпадают; SBOM присутствует.
- [ ] До публикации полного пакета собран и проверен соответствующий исходный
  код всех статически связанных зависимостей `libmpv`. Пока этот пункт не
  выполнен, portable-сборку и установщик не распространяют.
- [ ] Portable-сборка распакована в новый каталог и использует только свой
  `portable_config`.
- [ ] Чистая установка для текущего пользователя не требует прав
  администратора и не затрагивает другие установки mpv.net.
- [ ] Обновление сохраняет `%LOCALAPPDATA%\CensorPlayer`; откат восстанавливает
  точную предыдущую версию и не перезаписывает изменённый `portable_config`.
- [ ] Обычное удаление убирает файлы программы, но сохраняет данные
  пользователя; отдельная опция, выключенная по умолчанию, удаляет и их.
- [ ] В каталоге расширения есть только `CensorExtension.dll`; старых DLL и
  файлов `.deps.json` нет.

## Загрузчик, меню и интерфейс — блокирующие проверки

- [ ] Холодный запуск через `mpvnet.com` не вызывает исключений загрузчика.
- [ ] `Ctrl+Alt+C` и статическое меню `Цензура` открывают одно окно, которое не
  зависает.
- [ ] Вкладки `Текущий фильм / Интервалы / Настройки / Диагностика` доступны с
  клавиатуры, читаемы при масштабировании DPI, текст интерфейса остаётся
  русским.
- [ ] Меню и горячие клавиши открывают выбор файла, перезагружают и отключают
  расписание; работают F7/F8, навигация, сохранение и диагностика. Динамический
  статус виден в окне и OSD.
- [ ] Время от выбора файла до появления сводки измерено отдельно и не
  превышает 500 мс.
- [ ] Ручное перетаскивание из Проводника Windows загружает TXT, SRT и WebVTT.
- [ ] Если найдено несколько sidecar-файлов, список идёт в порядке
  TXT → SRT → VTT.

## Редактор и данные — блокирующие проверки

- [ ] Работают добавление, удаление, дублирование, объединение и разделение
  интервалов, фиксация времени, сдвиг на ±100 мс, сдвиг всех интервалов,
  переход к предыдущему и следующему интервалу, предпросмотр, а также отмена и
  повтор последних 100 действий.
- [ ] Черновик с ошибками нельзя применить или сохранить.
- [ ] `Сохранить` записывает временные метки без смещения и отдельный `offset-ms`,
  создаёт `.bak`; после импорта SRT/VTT по умолчанию используется канонический
  `.censor.txt`.
- [ ] При внешнем изменении файла можно выбрать `Перезаписать`,
  `Сохранить как…` или `Отмена`.
- [ ] Несохранённый черновик переживает переход A → B и перезапуск: он хранится
  в одном файле восстановления без пути к медиа. После сохранения или отказа
  от черновика этот файл удаляется.
- [ ] По умолчанию диагностический ZIP не содержит расписание и пути к файлам;
  расписание добавляется только с согласия пользователя.

## Работа приложения — блокирующие проверки

- [ ] После нажатия `Применить` появляется ожидаемый `@censor_blur_000`, а старый активный
  фильтр размытия не снимается при ошибке разбора, компиляции или применения
  нового расписания.
- [ ] Профили меняют `vf` по схеме `30/2 → 40/2 → 50/3`, используя интервалы из
  памяти. Расписание повторно не читается, пользовательский `vf` не удаляется.
- [ ] Размытие активно на `start_ms` и отсутствует точно на `end_ms`; при
  обычном и ненулевом PTS время совпадает с `time-pos`.
- [ ] Перемотка, пауза и продолжение, переход по главам, `watch-later` и
  скорости `0.5x/1x/1.5x/2x` не создают дрейфа.
- [ ] Переход A→B→C, смена файла во время выбора, разбора, компиляции или
  применения расписания, два одновременно открытых окна выбора, а также
  перетаскивание, отключение и смена профиля во время применения не публикуют
  устаревшее состояние.
- [ ] Фильтр восстанавливается после каждой из четырёх разнесённых по времени
  потерь. После трёх последовательных ошибок серия повторных попыток
  ограничивается, устойчивое чтение состояния сбрасывает счётчик, а
  воспроизведение не остаётся на паузе.
- [ ] Выход во время диалога, применения, восстановления или сброса буфера
  журнала не приводит к зависанию или сбою.
- [ ] Разбор, нормализация и компиляция 1 000 интервалов занимают не более
  250 мс.

## Оборудование и выпуск — блокирующие проверки

- [ ] Короткая проверка корректности 1080p30/60 пройдена на Intel, NVIDIA, AMD
  и в режиме программного декодирования.
- [ ] Один полный фильм 1080p прошёл длительный прогон: не было кадров без
  размытия, устаревшего расписания, потери фильтра и рассинхронизации звука и
  видео.

## Принятое неблокирующее ограничение — issue #3

Синтетический 4K30 с `hwdec-current=no` на RTX 4060 показал:

| Профиль | Пропущено |
|---|---:|
| Умеренное 30/2 | 52 / 90 |
| Сбалансированное 40/2 | 53 / 90 |
| Максимальное 50/3 | 56 / 90 |

Тест производительности не пройден, но для P0 результат не блокирующий: каждый
показанный кадр прошёл через `@censor_blur_000`. Проверка на типичном реальном
4K-видео, загрузка CPU/GPU, синхронизация звука и видео, переходы при
перемотке и смене профиля, а также OBS Window Capture отслеживаются в
[issue #3](https://github.com/CBEPX/mpvnet-censor-extension/issues/3).

Если не пройден хотя бы один блокирующий пункт, PR остаётся черновиком. Отчёт
должен содержать точный SHA-256 пакета; после исправления затронутый раздел
проверяется заново.
