# CensorPlayer для mpv.net

Расширение для стандартного
[mpv.net](https://github.com/mpvnet-player/mpv.net) под Windows x64. Оно
размывает весь кадр по интервалам из TXT, SRT или WebVTT. Расписание действует
только во время текущего сеанса воспроизведения. Базы фильмов, сетевых функций,
отпечатков файлов и автоматического обновления нет.

Лицензия проекта — [GPL-2.0-only](LICENSE).

## Установка

Публичный portable-пакет и установщик пока не выпускаются. CI собирает и
проверяет их на временном Windows runner, но публикует только DLL расширения,
его исходный код и сопроводительные файлы. Перед распространением полного
пакета нужно зафиксировать соответствующий исходный код всех статически
связанных зависимостей штатного `libmpv`.

После снятия этого ограничения выпуск будет содержать изолированную
portable-сборку, установщик для текущего пользователя, контрольные суммы и
SPDX SBOM.

Установщик размещает программу в
`%LOCALAPPDATA%\Programs\CensorPlayer`. Настройки, файлы восстановления, журналы
и диагностические данные хранятся в `%LOCALAPPDATA%\CensorPlayer`. При
интерактивном удалении деинсталлятор предлагает удалить пользовательские данные;
по умолчанию эта опция выключена. Тихое удаление сохраняет данные и файлы из
`portable_config`, если явно не передать параметр `/DELETEUSERDATA=1`.

При обновлении установщик заменяет `CensorExtension.dll`, но не перезаписывает
уже существующие `input.conf`, `mpv.conf` и `mpvnet.conf`, даже если они не
менялись. Новые привязки клавиш и настройки из поставки нужно вручную объединить
со своими файлами.

Будущая RC-сборка не будет подписана Authenticode, поэтому Windows SmartScreen
может показать предупреждение.

Чтобы вручную установить только расширение, скопируйте единственный файл
`CensorExtension.dll` в каталог:

```text
<MPVNET_CONFIG>\extensions\CensorExtension\
```

Расширение и точный readback фильтров проверены с mpv.net `7.1.2.0` из
`deps.lock.json`. Другие версии пока не поддерживаются: их libmpv может иначе
представлять `vf`/`af`. При несовместимости расширение безопасно оставит
воспроизведение на паузе; снять её можно через «Цензура → Отключить».

Удалите оставшиеся от ранних сборок `Censor.Core.dll` и
`CensorExtension.deps.json`, затем объедините [examples/input.conf](examples/input.conf)
со своим `input.conf`. Portable-сборка уже содержит собственный изолированный
`portable_config` и статическое меню `Цензура`.

## Использование

Откройте фильм и выберите `Цензура → Интервалы…`. На нужной сцене нажмите F7,
а в её конце — F8. Повторите это для остальных сцен, затем нажмите
`Применить интервалы`. Заранее создавать или загружать файл не нужно.

Кнопка `Сохранить файл` впервые предложит
`<каталог фильма>\<имя фильма>.censor.txt`; путь всегда подтверждает
пользователь. После сохранения повторное нажатие записывает тот же файл без
нового диалога. Окно содержит три вкладки:

- `Интервалы` — обычные действия видны сразу, а импорт, ручные смещения,
  Save As и экспорт находятся под кнопкой `Дополнительно`;
- `Настройки` — размытие, компрессия звука и автоматические функции; числовые
  параметры свёрнуты в `Расширенные параметры`;
- `Диагностика` — технические пути, состояние фильтров и экспорт ZIP с
  защищёнными псевдонимами путей.

Если фильм сменился при несохранённых изменениях, расширение не применит их к
новому фильму. В окне можно сохранить их для прежнего фильма, перенести на
текущий или удалить.

Если `settings.json` создан более новой версией и обычное сохранение
заблокировано, на вкладке `Диагностика` можно явно перезаписать его настройками,
которые сейчас показаны в окне. Исходный файл останется в
`settings.json.pre-repair` и не будет затронут обычными сохранениями.

Полный формат сохранения — `*.censor.txt`. Импорт TXT, SRT и WebVTT доступен
под кнопкой `Дополнительно`. SRT и WebVTT доступны как экспорт
копии: они не содержат метаданные файла интервалов и не отмечают изменения
сохранёнными. При ручном импорте SRT или WebVTT проигрыватель отдельно
предупреждает, что каждый фрагмент субтитров станет интервалом размытия.
Входные файлы расписаний и субтитров должны быть сохранены в UTF-8.
При перезаписи расписания, SRT или WebVTT предыдущая версия остаётся рядом в
файле с суффиксом `.bak`.

Профили размытия:

- `Умеренное`: `sigma=30`, `steps=2`;
- `Сбалансированное`: `sigma=40`, `steps=2` — по умолчанию;
- `Максимальное`: `sigma=50`, `steps=3`.

Компрессия звука по умолчанию выключена. В настройках доступны четыре пресета:

- `Фильмы — сбалансированная`;
- `Аниме — мягкая`;
- `Ночной режим`;
- `Адаптивное выравнивание`.

Пресет применяется сразу и подтверждается сообщением на экране. Расширение
меняет только фильтр `@censor_audio_compression`, не затрагивая остальные
аудиофильтры. Для обработки нужен декодированный PCM-звук: при HDMI/S/PDIF
passthrough компрессия не работает.

Префикс видеофильтров `@censor_blur_*` зарезервирован расширением. Не
используйте его для собственных фильтров `vf`.

Расширение принимает следующие сообщения `script-message`:

```text
censor-open
censor-pick
censor-load "C:\path\Film.censor.txt"
censor-apply
censor-reload
censor-disable
censor-mark-start / censor-mark-end
censor-set-start / censor-set-end
censor-previous / censor-next
censor-save
```

## Формат расписания

Минимальный валидный `Film.censor.txt`:

```text
00:12:03.250 --> 00:12:07.900
00:24:18.100 --> 00:24:23.450 | Необязательная заметка
```

Расширенный пример:

```text
# censor-timeline: 1
# title: Example Film
# media-duration-ms: 7200123
# lead-in-ms: 150
# lead-out-ms: 250
# offset-ms: 0

00:12:03.250 --> 00:12:07.900 | Сцена 1
```

P0 поддерживает только `# censor-timeline: 1`; другая версия формата
отклоняется. `media-duration-ms` — необязательная длительность фильма в
миллисекундах. Она помогает обнаружить расписание от другой версии монтажа:

- разница до 2 000 мс допустима;
- при ручной загрузке большую разницу можно подтвердить;
- sidecar-файл с большой разницей автоматически не применяется;
- если метаданных нет, появляется предупреждение, но ручная загрузка разрешена.

Границы полуоткрытые: `[start_ms, end_ms)`. Смещение хранится в отдельном поле
метаданных (`offset-ms`) и не меняет временные метки. При сохранении свободные
строки-комментарии `# ...` переносятся в блок заголовка перед интервалами. Полная
грамматика описана в [ТЗ, раздел 7](docs/TZ.md#7-пользовательский-формат-расписания).

Имена sidecar-файлов рядом с фильмом должны точно соответствовать шаблону:

```text
Film.mkv
Film.censor.txt
Film.censor.srt
Film.censor.vtt
```

Если найдено несколько вариантов, расширение показывает список и не выбирает
молча.

## Сборка

Нужны .NET SDK `10.0.302` и Git:

```sh
bash scripts/restore-mpvnet.sh
dotnet restore CensorPlayer.sln --locked-mode
dotnet build CensorPlayer.sln --configuration Release --no-restore
dotnet test CensorPlayer.sln --configuration Release --no-build --no-restore
```

Скрипт подготовки зависимости для сборки работает на macOS arm64 и Windows
x64. Другие платформы, включая Linux и Intel Mac, пока не поддерживаются.
Хеш собранного `libmpvnet.dll` привязан к .NET SDK `10.0.302`: при обновлении
SDK его нужно заново проверить и осознанно обновить в `deps.lock.json`. Хеши
для macOS и Windows проверяются независимо. Сейчас они совпадают благодаря
воспроизводимой сборке, но после изменения SDK или цепочки сборки могут
разойтись.

При осознанном обновлении SDK сначала измените `global.json` и поле
`dotnetSdk.version` в `deps.lock.json`. Затем запустите
`scripts/restore-mpvnet.sh` на macOS arm64 и Windows x64, сверьте напечатанные
SHA-256 и только после этого обновите оба значения `compileReferenceSha256`.
Повторный запуск скрипта и CI должен пройти уже с новыми закреплёнными хешами.

Чтобы собрать пакет для Windows:

```powershell
.\scripts\package-windows.ps1 -Version 1.3.2-rc.1
```

## Что уже проверено и ограничение 4K

Проверка коммита `440269a` из PR на реальном компьютере с Windows
подтвердила загрузку расширения из одного DLL-файла, видимое размытие,
переключение профилей, сохранение пользовательского `vf`, работу контроля
и восстановления фильтра, режимы 1080p30/60 и защиту от гонок состояния между
сеансами. На синтетическом видео 4K30 при `hwdec-current=no` пропускается больше
половины кадров, но все показанные кадры проходят через фильтр цензуры. Это
известное ограничение плавности, а не подтверждённая утечка кадров без
размытия. В этой конфигурации `lavfi/gblur` работал при `hwdec-current=no`,
поэтому нагрузку программной фильтрации нужно учитывать при выборе пресета.
Проверка на типичном 4K-видео и в OBS продолжается в
[issue #3](https://github.com/CBEPX/mpvnet-censor-extension/issues/3).

Перед выпуском portable-сборка и установщик должны повторно пройти
[проверку Windows P0](docs/WINDOWS_PHASE0.md) для точного SHA-256 каждого
пакета.

Дополнительно: [ТЗ](docs/TZ.md),
[ADR-003](docs/adr/ADR-003-session-scoped-schedules-no-database.md) и
[план выполнения](task_plan.md).
